# 食材状态识别说明

这个目录归档的是早期食材状态识别实验，主要目标是尝试识别食材的生、熟、焦糊等状态。它和当前 RGB/IR/SAM2 食材温度检测主线不是同一条主流程，目前没有被 `core/TrackFood.py` 调用。

## 当时的算法思路

这套实验主要以炒蛋状态识别为例，尝试把食材状态划分为三类：

- `raw`：生 / 未熟
- `done`：已熟
- `burnt`：焦糊

核心训练脚本是 `classify/train.py`，采用 EfficientNet-B3 迁移学习：

- 使用 ImageNet 预训练的 EfficientNet-B3 作为 backbone。
- 替换最后分类头，输出 `raw / done / burnt` 三分类结果。
- 第一阶段冻结 backbone，只训练分类头，使分类层先快速收敛。
- 第二阶段解冻全部网络，用较小学习率微调。
- 训练中使用随机裁剪、翻转、旋转、颜色扰动等增强，尝试模拟锅内光照和拍摄变化。
- 对 `burnt` 和 `raw` 类别设置了更高权重，目的是缓解样本不平衡并提高焦糊类召回。

推理脚本主要是 `classify/infer.py`，包含：

- 单张图片分类。
- 视频逐帧分类。
- 连续多帧 `burnt` 置信度超过阈值后的焦糊报警逻辑。
- `FoodStateClassifier` 类，原本预留为后续被主流程调用的模块接口。

## 暂未继续推进的原因

- 缺少足够干净、稳定、可泛化的训练数据。
- 早期通过爬虫或视频切帧得到的食材图片质量较差，存在画面不干净、主体不明确、菜品状态标签不可靠、拍摄条件混杂等问题，不适合作为稳定训练集。
- 不同食材、不同锅温和不同光照下，生熟焦状态的外观差异不稳定。
- 缺少一套明确的食材状态评判标准，例如什么程度算熟、什么程度算焦，以及不同菜品之间是否共用同一标准。
- 当前项目主线已经转向 RGB/IR/SAM2 食材温度检测，食材状态识别暂时只作为历史实验归档。

后续如果要重新启动这条路线，建议先建立小规模高质量标注数据集，并先定义清楚状态分类标准，再继续训练或评估模型。
